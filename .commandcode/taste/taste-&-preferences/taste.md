# Taste & preferences
- Prefers premium, cinematic, interactive product-experience landing pages (Apple Vision Pro / Linear / Vercel / Raycast quality) over conventional SaaS layouts; explicitly rejects the generic hero pattern of headline + subtitle + two buttons + background particles + feature cards. Confidence: 0.95
- Wants the product demonstrated rather than described — the page should let visitors *experience* the product's core loop through scroll-driven storytelling, not merely tell them what it does. Confidence: 0.9
- Treats reference sites (SharpLink, Oxigen, Van Lent, Linear, Vercel, Apple) as sources of interaction quality, pacing, and motion only — wants an original identity, never copied design, assets, or branding. Confidence: 0.9
- Cares about a high differentiation/wow quality bar — the result should feel like an interactive product launch, not "a nice SaaS website." Confidence: 0.9
- Assigns clear animation-library responsibilities: GSAP (+ ScrollTrigger) for scroll choreography, camera, timelines and counters; React Three Fiber / Three.js for the 3D scene; Framer Motion only for small UI transitions (menus, buttons, dialogs). Avoids using multiple libraries for the same animation. Confidence: 0.9
- Prefers Clerk for authentication (sign-in, sign-up, sessions, organizations, roles, permissions) — explicitly "do not build custom authentication"; secret credentials must stay server-side, the browser only ever sees the publishable key. Confidence: 0.95
- Performance-first for immersive/3D experiences: lazy-load Three.js and heavy assets so they never block first render, use instancing and compressed geometry, cap devicePixelRatio, tier scene complexity by device, and provide a graceful fallback when WebGL is unavailable. Confidence: 0.9
- On mobile/weak devices, build a simplified 3D scene rather than shrinking the desktop one — reduce particles, geometry, post-processing and camera movement while preserving the storytelling. Confidence: 0.9
- Respects `prefers-reduced-motion`: reduce camera movement, disable scroll-scrubbed animations and parallax, cut particle counts, and keep content readable. Confidence: 0.9
- Provides detailed, prescriptive briefs with explicit "do not" lists and a concrete quality bar, and expects the codebase to be inspected before writing code. Confidence: 0.85
- Runs the agent in "yolo" mode (auto-approve): wants autonomous execution of commands and changes without per-step confirmation prompts; re-issues `cmd --yolo` to keep the agent going without adding new instructions. Confidence: 0.9
- When something appears broken or behaves unexpectedly, wants a plain-language explanation of what is actually happening and why (the root-cause mechanism), not just a fix — explain in simple, non-jargon terms with concrete next steps. Confidence: 0.75
- Communicates informally and with emotional/urgent tone when blocked or frustrated (typos like "sihn in", "what to doooo??", "at all") — expects a direct, plain-language, actionable answer with concrete next steps, not formal or lengthy framing. Confidence: 0.6
- Reports bugs by pasting the raw error/console message with little or no context (e.g., "Failed to load resource: the server responded with a status of 404") and expects the agent to investigate and diagnose the root cause itself rather than asking for details. Confidence: 0.55
- Wants the dev server started with `npm run dev` (npm commands), even though the repo is set up for pnpm — use npm when invoking run/dev scripts on the user's behalf. Confidence: 0.6
- When asking how to run something, wants the exact, copy-paste-ready command verbatim in a code block — not a paraphrased explanation of what to type. Confidence: 0.6
- Extends the "unlike anything seen before" quality bar beyond landing pages to feature implementations (e.g., the PDF report generator) — core features should also feel exceptional, not just the marketing surface. Confidence: 0.6
- Expects previously shared configuration (e.g., a Neon connection string given "earlier") to be remembered or found in the repo rather than re-asked for; wants the agent to continue from prior context instead of starting over. Confidence: 0.7
- Wants the whole stack wired end-to-end — demo auth account, backend, and database all configured and connected ("all must be configured"), not left as placeholders or mock-only stubs. Confidence: 0.7
